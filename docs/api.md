# Campaign Agent API

Реализация: `backend/app/main.py`, схемы: `ai/models/workspace.py`, выполнение: `ai/pipelines/runtime.py`.

## HTTP

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Статус backend, конфигурации официальной среды и необязательного LLM; без внешних запросов |
| `GET /api/workspace` | Снимок `schema_version: 1` непосредственно в корне JSON, совместимый с frontend |
| `POST /api/datasets` | Сырое тело CSV (`text/csv`) или JSON (`application/json`), до 20 MiB; результат — обновлённый снимок |
| `POST /api/agent/runs` | Пустое тело; запускает существующий Agent, возвращает `202 {run_id, state}` |

`GET /docs` — OpenAPI-интерфейс. Для raw upload используйте указанный Content-Type, не multipart.
Загрузка данных — максимум 30 секунд, валидация исполняется вне event loop.
Запуск изолирован в отдельном процессе, максимум 300 секунд и 18 обращений к пилотам.
Истечение срока завершает процесс и переводит снимок в FAILED. При ошибке непроверенные остатки ресурсов скрываются, чтобы не выдавать старый баланс за актуальный. Повторный POST во время выполнения возвращает 409.
Ошибки: `{"success":false,"error":{"code":"...","message":"..."}}`, без входных секретов и traceback.
HTTP 413 — превышение размера, 415 — формат, 422 — данные, 409 — состояние/отсутствие среды, 429 — занятые worker-процессы.

API использует случайный `HttpOnly; SameSite=Strict` cookie `nx_session`, отдельный для браузерной сессии.
Frontend подключается через тот же origin (Vite proxy или статика FastAPI); при прямых HTTP-запросах сохраняйте cookie.
CORS разрешает только localhost/127.0.0.1 на портах 5173, 4173, 8000.
Изменяющие запросы с постороннего Origin блокируются. Данные не записываются на диск и не передаются LLM.
Это локальная сессия, не система аутентификации. Не публикуйте текущий сервер в интернет.

## Загрузка реальных данных

CSV представляет только `customer_profile`. Требуются колонки:

| Поле | Ограничения |
| --- | --- |
| `id` | Непустая строка, уникальна, до 256 символов; aliases: `customer_id`, `subscriber_id` |
| `current_tariff` | Непустой ID тарифа |
| `arpu` | Фактический неотрицательный конечный ARPU; alias: `arpu_3m_avg` |
| `predicted_arpu` | Необязательная уже рассчитанная моделью величина; API её не генерирует |
| `arpu_segment`, `data_segment`, `call_segment` | Необязательные существующие категории |

До 100 000 строк. Если указан `arpu_segment`, он должен быть заполнен у всех строк: отсутствующий сегмент не превращается в wildcard-таргетинг.
Неизвестные поля, конфликтующие aliases, повторные ID/заголовки, пустые/повреждённые файлы, NaN/Infinity и boolean вместо чисел отклоняются.
При ошибке загрузки предыдущий набор остаётся доступен.

JSON — объект с `customer_profile` (массив строк описанного выше формата) и optional коллекциями:

- `tariffs`: до 500 объектов, `id`, optional `name`, `price`, `data_gb`, `minutes`, целое `sms`;
- `channels`: до 50 объектов, `id`, `cost` (неотрицательная стоимость контакта), `effectiveness` (положительный коэффициент официального кейса), optional `name`;
- `change_tariff`: до 100 000 реальных исторических переходов с `current_tariff`, `target_tariff`, `arpu_before` > 0, `arpu_after` >= 0.

Если каталог тарифов передан, все текущие/исторические тарифы должны входить в него.
API принимает содержание данных, не локальные пути и не команды. Имя файла не используется backend.
Snapshot JSON результатов и dataset JSON — разные форматы; используйте соответствующее действие в Connect source.

## Подключение официальной среды

В текущем репозитории нет evaluator/официального `env.run_pilot`. Его результаты не симулируются.
Переменная `NX_ENV_FACTORY` задаётся владельцем сервера, никогда HTTP-клиентом. Формат — `package.module:function`;
модуль должен быть реальным `.py` внутри PROJECT_ROOT. Нельзя задавать пути, выражения или внешние модули.

Factory получает один аргумент: `None`, если используются её собственные официальные данные, либо словарь:
`customer_profile` (pandas DataFrame), `tariffs` и `channels` (списки), `change_tariff` (DataFrame).
Factory должна создать новую изолированную среду. Нельзя совместно использовать изменяемый бюджет/состояние разных сессий.
Если формат официальной среды отличается, адаптер переводит его в этот явный контракт:

- `customer_profile`: DataFrame по схеме загрузки;
- `tariffs`, `channels`: непустые каталоги по схеме выше (списки либо DataFrame);
- optional `change_tariff`: DataFrame с историческими переходами;
- `remaining_budget`: конечное неотрицательное число;
- `remaining_contacts`, `pilots_left`: неотрицательные целые;
- `run_pilot(target_tariff, channel, n_customers, filter_current_tariff, filter_arpu_segment=None)`.

Пилот действительно обращается к официальной среде. После успешного вызова `pilots_left` уменьшается на 1,
`remaining_contacts` — на фактический размер выборки (1..запрошенный размер), бюджет — на размер × стоимость канала.
Эти изменения проверяются; расход не подменяется предполагаемым успешным результатом. Ошибочный пилот не повторяется автоматически.

Рекомендуемый результат пилота — mapping с `relative_effect` (0.1 = 10%) и `sample_size`.
Совместимость сохранена с явными ARPU before/after, относительными effect/uplift, процентными полями `effect_pct`/`effect_percent`,
абсолютным ARPU delta и gross revenue delta. `%` всегда делится на 100, включая 0.5%.
Неоднозначные `profit`, `net_result` и произвольные `*_change` не интерпретируются как uplift.
Optional `confidence` (0..1) и `uncertainty` (неотрицательная) передаются только когда официальная среда их действительно рассчитала.
При отсутствии этих полей они не генерируются; карта frontend честно сообщает об отсутствии данных для точки.

Агент сохраняет публичный `Agent.act(env)`. Он строит кандидатов из реальных групп и тарифов,
использует историю, исследует/подтверждает реальные пилоты и выбирает положительный портфель в пределах бюджета/контактов.
Отсутствие подходящих кампаний — корректный пустой результат, не принудительная выдуманная кампания.
Сохранённая стратегия использует shrinkage и эвристический штраф риска. Это **не статистический confidence** и не новая обученная ML-модель.
`expected_impact` — расчётная консервативная оценка, не фактически полученный доход.

`audience_size` кампании — вся аудитория, соответствующая фильтру; пересекающиеся кампании запрещены.
Ресурс контактов учитывает расходы пилотов и резерв рекомендаций. Существующий Agent не передаёт списки ID для исключения участников пилота:
если официальный кейс запрещает повторный контакт между пилотами и финальной кампанией, эту семантику нужно согласовать с официальным evaluator,
прежде чем считать портфель допустимым. Без среды такое соответствие не утверждается.
`campaigns_allocated` — резерв, кампании API никому не отправляет.

## Объяснения

По умолчанию объяснения формируются из фактических вычислений, событий и источников evidence.
Необязательные `OPENAI_API_KEY` и `OPENAI_MODEL` включают провайдер из `ai/models/llm.py`;
`OPENAI_BASE_URL` по умолчанию `https://api.openai.com/v1`, допускается только HTTPS URL без встроенных credentials/query.
Используется [Responses API с JSON Schema](https://developers.openai.com/api/docs/guides/structured-outputs).
Модель выбирает порядок ID из закрытого набора проверенных фактов; выводимый текст берётся только из серверного набора.
Произвольные цифры, новые факты, tool calls и неизвестные ID не принимаются.
Абонентские строки, API-ключи и история диалогов не включаются в контекст. Чата в существующем интерфейсе нет.

Один LLM-вызов на запуск, максимум 2 попытки при timeout/сетевой ошибке/429/5xx, connect timeout 3 секунды, request timeout 8 секунд,
короткая ограниченная задержка, максимальный ответ 64 KiB. Ошибка 401/403, отказ, невалидный формат или недоступность модели
сохраняют детерминированное объяснение и создают понятное предупреждение. Startup и health не вызывают LLM.
`llm_available` в health означает корректную конфигурацию, а не подтверждённую проверку ключа у провайдера.

## Проверенные границы

Тесты в `tests/ai` и `tests/backend` используют только тестовые fixtures и HTTP mocks.
Они проверяют полный путь HTTP → существующий Agent → инструментальный тестовый env → снимок,
но не заменяют проверку на официальном evaluator. Реальный OpenAI без ключа также не проверен.
